Architected thread-safe content-based caching with hash keys for chromosomes
Here's the cache wired in. Two changes: (1) how cache is declared/used, and (2) checking/populating it inside the two parallelEvaluate* functions, since that's where you have a stable single-threaded point to safely read/write it before dispatching work to the pool.

1. Replace the cache member + add a mutex + hash helper
cpp
// map<int,Chromosome> cache;   // <-- remove this
std::unordered_map<uint64_t, double> cache;   // key: content hash, value: fitness
std::mutex cacheMutex;
Add a helper that hashes a chromosome by its actual gene content (position + type), order-independent so two chromosomes with the same radar placements in a different order still hit the cache:

cpp
static uint64_t hashChromosome(const Chromosome& cn) {
    std::vector<uint64_t> geneHashes;
    geneHashes.reserve(cn.radar.size());
    for (const auto& g : cn.radar) {
        uint64_t h = std::hash<int>()(g.r);
        h ^= std::hash<int>()(g.c)         + 0x9e3779b97f4a7c15ULL + (h << 6) + (h >> 2);
        h ^= std::hash<int>()(g.typeIndex) + 0x9e3779b97f4a7c15ULL + (h << 6) + (h >> 2);
        geneHashes.push_back(h);
    }
    std::sort(geneHashes.begin(), geneHashes.end()); // order-independent
    uint64_t result = geneHashes.size();
    for (auto h : geneHashes)
        result ^= h + 0x9e3779b97f4a7c15ULL + (result << 6) + (result >> 2);
    return result;
}
2. parallelEvaluatePopulation — skip eval on cache hit, populate on miss
cpp
void parallelEvaluatePopulation(
    std::vector<Chromosome>& pop, Global& globalRef,
    const FeasibleGrid& base_grid, bool writePng = false,
    const FeasibleGrid& aoi_grid = {})
{
    auto startTime = std::chrono::high_resolution_clock::now();

    std::vector<std::future<void>> futures;
    std::vector<size_t>   pendingIdx;
    std::vector<uint64_t> pendingKeys;
    futures.reserve(pop.size());
    pendingIdx.reserve(pop.size());
    pendingKeys.reserve(pop.size());

    std::vector<RadarConf> empty(0);

    for (size_t i = 0; i < pop.size(); i++) {
        uint64_t key = hashChromosome(pop[i]);

        bool hit = false;
        double cachedFitness = 0.0;
        {
            std::lock_guard<std::mutex> lock(cacheMutex);
            auto it = cache.find(key);
            if (it != cache.end()) { hit = true; cachedFitness = it->second; }
        }

        if (hit) {
            pop[i].fitness = cachedFitness;
            continue; // skip enqueueing — no coverage recompute needed
        }

        pendingIdx.push_back(i);
        pendingKeys.push_back(key);

        if (conf.homo.is_case) {
            futures.push_back(pool.enqueue(
                evaluate_fitness,
                std::ref(globalRef), std::ref(base_grid),
                std::ref(pop[i]), (int)i,
                weights, homoParams, writePng, empty, std::ref(aoi_grid), wf, overlapping_factor));
        } else {
            futures.push_back(pool.enqueue(
                evaluate_fitness,
                std::ref(globalRef), std::ref(base_grid),
                std::ref(pop[i]), (int)i,
                weights, homoParams, writePng, std::ref(conf.hetero.radars), std::ref(aoi_grid), wf, overlapping_factor));
        }
    }

    for (auto& f : futures) f.wait();

    // Populate cache with freshly-computed results
    {
        std::lock_guard<std::mutex> lock(cacheMutex);
        for (size_t k = 0; k < pendingIdx.size(); k++)
            cache[pendingKeys[k]] = pop[pendingIdx[k]].fitness;
    }

    auto endTime = std::chrono::high_resolution_clock::now();
    std::chrono::duration<double, std::milli> duration = endTime - startTime;
    totalFitnessEvalTimeMs += duration.count();
}
Note I merged your if(conf.homo.is_case)/else branches into one function body (they were identical except for the radar arg) — saves duplicating the cache logic twice. Behavior is unchanged.

Why this shape and not caching inside evaluate_fitness
evaluate_fitness/evaluate_auto_fitness are static and run inside pool worker threads with no access to non-static members like cache. Doing the lookup/insert in parallelEvaluate* keeps all cache access on threads that already own a lock scope, and — more importantly — lets you skip enqueueing the coverage computation entirely on a hit, rather than paying for calculate_radar_coverage_overlap and just discarding the result. That's the actual win, since coverage calc is almost certainly your bottleneck, not the fitness arithmetic.

One thing worth deciding
Elitism (nextGen.push_back(population.back())) carries the same Chromosome object forward each generation, so its hash will always hit after the first eval — good, that's free. But note bubble/id gets reassigned on crossover/mutation regardless of whether content changed (e.g. mutation with 0% actual mutation rate hits due to distR(rng) < mutationRate per-gene still resulting in an identical chromosome by chance) — that's fine, since the hash is content-based, not id-based, so it'll still correctly hit the cache even though id differs.

If you expect very long runs, you may want to cap cache size (e.g. LRU or periodic clear) since it grows unbounded — feasible grids can produce a huge combinatorial space, but in practice repeated exact-match chromosomes (mostly from elitism/low mutation) are what you're targeting, so growth should stay modest.
